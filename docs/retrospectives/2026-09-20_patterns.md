# RETROSPECTIVE — 2026-09-20 Session Patterns

**Purpose:** A future session should read this in <2 minutes and know what to watch for. Not a blow-by-blow — the recurring categories, their root causes, and the concrete rules that prevent recurrence.

---

## 1. Gate-Skipping

**What happened:** Applied/committed before explicit "approved" message — 3× this session. Each time caught and corrected, but the pattern repeated.

**Root cause:** Treating chained "next item" instructions as *inherited approval* rather than fresh gates. The operator says "do A, then B, then C" — the agent hears "approval for A, B, and C" instead of "approval for A; come back for B; come back for C."

**Rule (permanent):**
> **No action without a standalone "approved" message for *that specific action*.**  
> "Proceed through all" is the only phrase that grants multi-item approval. Absent that exact phrase, each item gets its own gate — show diff/plan → wait for "approved" → execute → verify → report → *stop and wait for next approval*.

---

## 2. Malformed Diffs

**What happened:** Hand-assembled or fuzzy-matched patches producing invalid Python (duplicated lines, missing minus-lines, mismatched hunks) — at least 2× this session.

**Root cause:** Patch tool's fuzzy matching + constructed content not matching actual file whitespace/indentation. The agent generated a diff from memory/assumption rather than reading the *exact current file content* first.

**Rule (permanent):**
> **Read the exact target lines from the live file immediately before writing any patch.**  
> `read_file(path, offset=X, limit=Y)` → construct diff with *those exact lines* as `old_string` → `patch()` → `py_compile` → test. No exceptions for "small/obvious" changes. If the same region fails twice, rewrite the whole function/file with `write_file` instead of a third patch.

---

## 3. Incomplete Sweeps Claimed Complete

**What happened:** "8 sites fixed, sweep done" when 7 more existed; same shape earlier with `is_active` guard audit (6→7→8 sites discovered incrementally).

**Root cause:** Narrow/targeted greps (`grep "credit_fill" engine/reconciler.py`) mistaken for exhaustive ones. The agent searched *one file* or *one pattern* and generalized to "all engine code."

**Rule (permanent):**
> **Exhaustive = cross-repo, multi-pattern, verified by count.**  
> Before claiming "sweep complete":  
> 1. `grep -rn "pattern" --include="*.py" .` (whole repo, not one dir)  
> 2. Count total matches, categorize by file/function  
> 3. List every match with file:line:context  
> 4. Only then state "N sites total, M fixed, K excluded (with reasons)"  
> 5. If new matches appear later, the sweep was incomplete — admit it, don't redefine "complete."

---

## 4. Confabulation Over Evidence

**What happened:** Printed a correct query result (`Bot 100999: None`) then wrote a contradictory narrative ("Bot 100999 DOES exist...") in the same message.

**Root cause:** Trusting an assumption/expectation ("the test fixture should still exist") over the evidence *just printed*. The narrative was written from memory/expectation; the query output was read but not *used* to derive the conclusion.

**Rule (permanent, added to HANDOFF.md Rule 8):**
> **When a message contains both raw tool output AND a prose conclusion about that output: re-read your own printed output one more time and check it against your conclusion sentence by sentence.**  
> If they don't match, the tool output is correct and the conclusion is wrong — *always*. Defer to printed evidence over whatever you expected or assumed. This applies even when the "expected" answer feels more plausible.

## Quick Reference Card for Next Session

| If you catch yourself… | Stop and… |
|------------------------|-----------|
| "The user said do A then B, so I'll do both" | Ask: "Is there a standalone 'approved' for B?" |
| Writing a patch without `read_file` first | Read the exact lines, then patch |
| "grep found 8 matches, sweep done" | `grep -rn` whole repo, count, list all |
| Writing a conclusion after printing a query | Re-read the query output; derive conclusion from it |
