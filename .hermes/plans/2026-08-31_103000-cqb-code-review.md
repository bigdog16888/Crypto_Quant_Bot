## 3. WHAT'S WRONG (needs fixing)

### 3.1 CRITICAL: WriteQueue Deadlock (engine crashed 2026-08-28)

**Evidence:** `engine.log` → `[WRITE-QUEUE] TIMEOUT waiting for task. Worker may be deadlocked. Timeout: 30s.`

**Root cause analysis:**
```python
# write_queue.py:87
if getattr(self, '_bypass', False) or threading.current_thread() == self._worker_thread:
    return fn(*args, **kwargs)
```

The bypass check is correct for pytest, but the worker thread identity check has a race:
1. Thread A calls `put_and_wait(seal_trade_state, ...)` — enqueues task, waits on event
2. Worker thread picks up task, executes `_seal_trade_state_internal`
3. Inside seal, it calls `credit_fill()` which calls `WriteQueue().put_and_wait()` again
4. Worker thread checks `threading.current_thread() == self._worker_thread` → True → bypass → executes inline
5. But the inner call may try to acquire a DB lock held by the outer call → deadlock

**The pattern exists in:**
- `ledger.py:99` — `credit_fill()` calls `put_and_wait(_credit_fill_internal, ...)`
- `ledger.py:512` — `seal_trade_state()` calls `put_and_wait(_seal_trade_state_internal, ...)`
- If `_seal_trade_state_internal` ever calls `credit_fill()` (or any `put_and_wait`), the worker deadlocks.

**Fix needed:** Audit all `put_and_wait` call sites for nested calls. Either:
- (a) Detect nested calls and execute inline (current bypass logic, but check DB lock ordering)
- (b) Use a reentrant lock instead of thread identity check
- (c) Document the invariant: "Never call put_and_wait from within a WriteQueue task"

### 3.2 CRITICAL: `strategy_config` Column Missing

**Location:** `database.py:3685`
```python
cursor.execute("SELECT strategy_config FROM bots WHERE id=?", (bot_id,))
```

**Actual column name:** `config` (verified via `PRAGMA table_info(bots)`)

**Impact:** `recompute_invested_from_orders()` succession-proof math is silently skipped for every bot. The `Math cross-ref failed for bot X: no such column: strategy_config` debug noise appears in test output.

**Fix:** One-line patch: `strategy_config` → `config`.

### 3.3 CRITICAL: `stop_db_worker` Import Broken

**Location:** `run_engine.py:219`
```python
from engine.ws_event_handlers import stop_db_worker
```

**Reality:** `ws_event_handlers.py` does NOT define `stop_db_worker`. This would crash every shutdown with ImportError.

**Fix:** Either restore the symbol or update the import. Likely renamed during INV-31 refactor.

### 3.4 HIGH: `ARCHITECTURE_DECISIONS.md` is Wrong

Claims:
- "Binance Futures must be in Hedge Mode: dualSidePosition = true"
- "Current testnet account is in One-Way Mode, which is why every hedge child has only ever netted into its parent"

**Reality:** The system is explicitly designed for One-Way mode. `exchange_interface.py:169`:
```python
ExchangeInterface._position_mode_hedge = False
```
The hedge feature is a BOT-LEVEL risk management tool (parent LONG + child SHORT internally), not exchange Hedge Mode.

**Impact:** Misleading docs could cause an operator to flatten positions and switch modes unnecessarily, losing the entire hedge architecture.

**Fix:** Rewrite `ARCHITECTURE_DECISIONS.md` to reflect One-Way design. Move the "Hedge Mode" section to a historical/abandoned ADR.

## 10. FINAL VERDICT

**The system is architecturally sound.** The proof-only reconciliation, 3-layer state model, and One-Way netting design are well-thought-out and well-documented in CODEBASE_GUIDE.md.

**The issues are operational, not architectural:**
- WriteQueue deadlock (needs lock-order audit)
- Broken imports (needs symbol restoration)
- Stale docs (needs rewrite to reflect One-Way design)
- Test failures (needs baseline classification)

**The code quality is functional but verbose:**
- Long functions need breaking down
- Dead code from retired features needs removal
- Naming conventions need standardization

**Recommendation:** Fix the 3 critical issues (deadlock, import, docs), complete the runner mixin migration, and backfill CHANGELOG. Then the system is ready for another production test run.
